Lifecycle of a run

Every scenario moves through four states—same idea as a machine lifecycle, for deals.

01

Describe

Goals, constraints, counterparties, BATNA.

02

Simulate

Agents play offer / counter / walk-away paths.

03

Rank

Orchestrator scores paths by utility and risk.

04

Brief

Primary, push, and walk-away moves—human-readable.

Hard boundary: LLMs may narrate the brief. They do not replace the simulation layer. Strategy comes from constrained multi-agent search, not from asking a model to “be a good negotiator.”

Cloud status: planned architecture and build phases—not a claim that every service is already in production.

How we use AWS

Four jobs the cloud must do well—mapped to concrete AWS services.

1. Training

Phase 1–2

Train and fine-tune multi-agent RL policies for negotiation environments (offer sequences, BATNA, multi-party games). Experiment tracking and checkpoint storage live next to the trainers.

SageMaker Training SageMaker HyperPod / GPU instances S3 model artifacts CloudWatch metrics

2. Simulation

Phase 1

Fan out thousands–millions of synthetic negotiation rollouts per scenario. Batch jobs for deep search; streaming workers for interactive “what if” runs.

AWS Batch ECS / Fargate SQS job queues ElastiCache (run state)

3. Inference

Phase 2

Serve briefs: ranked moves, risk flags, and chat-style explanations. Low-latency API for the product UI; optional larger models for narrative summary.

SageMaker Endpoints Amazon Bedrock (summaries) API Gateway + Lambda CloudFront

4. Data pipeline

Phase 2–3

Ingest deal context, anonymize where needed, version scenarios, and feed eval / offline learning loops. Separate raw customer data from training corpora.

S3 data lake AWS Glue Aurora / DynamoDB EventBridge KMS encryption

Infrastructure Development Roadmap

  • Now · MVP sim loop Single-region: Batch/ECS workers + S3 checkpoints + simple API. Prove “describe deal → ranked moves” end-to-end.
  • Next · Train / eval on SageMaker Move MARL training off laptops; log experiments; store reproducible artifacts.
  • Then · Product inference Managed endpoints + Bedrock for explanations; CloudFront for the web app.
  • Later · Hardened data plane Tenant isolation, KMS, audit logs, retention policies—needed before enterprise pilots.

Security & Compliance Strategy

How we protect deal context as the product moves from prototype to pilots.

Encryption TLS in transit; S3/DB encryption at rest with KMS.
Access IAM least privilege, no long-lived keys in clients, private subnets for workers.
Data handling Deal text treated as sensitive; optional customer-managed keys later.
Policies live Privacy · Terms on the marketing site today.

Cloud Infrastructure Overview

ShadowProxy’s Simulation Engine uses multi-agent reinforcement learning and game-theoretic utilities to rehearse high-stakes negotiations and emit ranked briefs. We plan MARL training on Amazon SageMaker, large-scale rollouts on AWS Batch/ECS, online inference via SageMaker Endpoints and Amazon Bedrock, and a secured S3 + Glue + Aurora/DynamoDB pipeline—with KMS and IAM from day one. LLMs narrate; they do not replace the simulation layer.
